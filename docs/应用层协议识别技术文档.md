# NetDefender 应用层协议识别技术文档

## 1. 概述

应用层协议识别（Application Layer Protocol Detection）是NIDS系统的核心功能之一，它能够识别网络流量中的应用层协议类型（如HTTP、TLS、DNS等），为后续的深度包检测、协议解析和威胁检测提供基础。

本文档基于Suricata 6.0.10的协议识别机制，针对NetDefender DPDK-based NIDS进行了简化和适配。

---

## 2. Suricata协议识别机制研究

### 2.1 核心架构

Suricata使用**三层识别机制**，按优先级排序：

```
┌─────────────────────────────────────────────────────────┐
│           应用层协议识别流程                               │
├─────────────────────────────────────────────────────────┤
│                                                           │
│  1. Pattern Matching (PM) - 模式匹配                     │
│     ├─ 基于MPM算法（AC/AC-KS/Hyperscan）                 │
│     ├─ 快速但可能误报                                     │
│     └─ 示例：检测HTTP方法"GET "、"POST "                  │
│                                                           │
│  2. Probing Parser (PP) - 探测解析                       │
│     ├─ 基于端口 + 深度协议解析                            │
│     ├─ 准确但需要端口配置                                 │
│     └─ 示例：端口443 + TLS握手验证                        │
│                                                           │
│  3. Protocol Expectation (PE) - 协议期望                 │
│     ├─ 基于协议关联（如FTP控制/数据通道）                 │
│     ├─ 用于动态端口协议                                   │
│     └─ 示例：FTP PORT命令创建数据通道期望                 │
│                                                           │
└─────────────────────────────────────────────────────────┘
```

### 2.3 识别流程

```c
AppProto AppLayerProtoDetectGetProto(
    AppLayerProtoDetectThreadCtx *tctx,
    Flow *f,
    const uint8_t *buf,
    uint32_t buflen,
    uint8_t ipproto,
    uint8_t flags,     // STREAM_TOSERVER/TOCLIENT
    bool *reverse_flow)
{
    AppProto alproto = ALPROTO_UNKNOWN;

    // 步骤1: Pattern Matching（如果未完成）
    if (!FLOW_IS_PM_DONE(f, flags)) {
        alproto = AppLayerProtoDetectPMGetProto(
            tctx, f, buf, buflen, flags, ...);
        if (AppProtoIsValid(alproto)) {
            return alproto;  // PM成功
        }
    }

    // 步骤2: Probing Parser（如果未完成）
    if (!FLOW_IS_PP_DONE(f, flags)) {
        alproto = AppLayerProtoDetectPPGetProto(
            f, buf, buflen, ipproto, flags, ...);
        if (AppProtoIsValid(alproto)) {
            return alproto;  // PP成功
        }
    }

    // 步骤3: Protocol Expectation
    if (!FLOW_IS_PE_DONE(f, flags)) {
        alproto = AppLayerProtoDetectPEGetProto(
            f, ipproto, flags);
        if (AppProtoIsValid(alproto)) {
            return alproto;  // PE成功
        }
    }

    return ALPROTO_UNKNOWN;
}
```

```c
// TLS Probing Parser
static AppProto SSLProbingParser(
    Flow *f, uint8_t direction,
    const uint8_t *input, uint32_t ilen,
    uint8_t *rdir)
{
    if (ilen < 3)
        return ALPROTO_UNKNOWN;

    // 检测TLS握手特征
    // SSLv2: 0x80 + length + 0x01 (Client Hello)
    if ((input[0] & 0x80) && (input[2] == 0x01)) {
        return ALPROTO_TLS;
    }

    // SSLv3/TLS: 0x16 (Handshake) + version + length
    if (input[0] == 0x16 &&         // Content Type: Handshake
        input[1] == 0x03 &&         // Version Major: 3
        (input[2] >= 0x00 && input[2] <= 0x03)) {  // Minor
        return ALPROTO_TLS;
    }

    return ALPROTO_FAILED;
}

// 注册Probing Parser（端口443）

    0,                   // min_depth
```

## 3. NetDefender简化设计

### 3.1 设计目标

1. **简化架构**：只实现PM + PP两层（PE暂不实现）
2. **DPDK适配**：适配DPDK的zero-copy和lcore模型
3. **高性能**：使用简单但高效的字符串匹配
4. **可扩展**：易于添加新协议

### 3.2 架构设计

## 4. 核心协议实现

### 4.1 HTTP协议识别

#### 识别特征

**ToServer（请求）**:
- Pattern: `"GET "`, `"POST "`, `"PUT "`, `"HEAD "`, etc.
- 位置: 数据包开头
- 特点: 忽略大小写

**ToClient（响应）**:
- Pattern: `"HTTP/1.0"`, `"HTTP/1.1"`, `"HTTP/2"`
- 位置: 数据包开头
- 特点: 忽略大小写

#### 注册代码

```c
void http_proto_register(void)
{
    // HTTP方法 (ToServer)
    static const char *http_methods[] = {
        "GET ", "POST ", "PUT ", "DELETE ", "HEAD ",
        "OPTIONS ", "PATCH ", "CONNECT ", "TRACE ", NULL
    };

    for (int i = 0; http_methods[i]; i++) {
        proto_detect_register_pattern(
            IPPROTO_TCP,
            APP_PROTO_HTTP,
            http_methods[i],
            strlen(http_methods[i]),
            0,  // offset
            PROTO_DETECT_DIR_TOSERVER,
            1   // nocase
        );
    }

    // HTTP版本 (ToClient)
    proto_detect_register_pattern(
        IPPROTO_TCP, APP_PROTO_HTTP,
        "HTTP/1.", 7, 0,
        PROTO_DETECT_DIR_TOCLIENT, 1
    );

    proto_detect_register_pattern(
        IPPROTO_TCP, APP_PROTO_HTTP,
        "HTTP/2", 6, 0,
        PROTO_DETECT_DIR_TOCLIENT, 1
    );
}
```

### 4.2 TLS协议识别

#### 识别特征

```
TLS Record Header:
  +------+------+------+------+------+
  | Type | Ver1 | Ver2 | Len1 | Len2 |
  +------+------+------+------+------+
    0x16   0x03  0x00-03

Type:
  0x14 = Change Cipher Spec
  0x15 = Alert
  0x16 = Handshake
  0x17 = Application Data

Version:
  0x0300 = SSLv3
  0x0301 = TLSv1.0
  0x0302 = TLSv1.1
  0x0303 = TLSv1.2
  0x0304 = TLSv1.3
```

#### Probing Parser实现

```c
static app_proto_t tls_probing_parser(
    const uint8_t *data, uint32_t data_len, uint8_t direction)
{
    if (data_len < 5)
        return APP_PROTO_UNKNOWN;

    // SSLv2 Client Hello: 0x80 + len + 0x01
    if ((data[0] & 0x80) && (data[2] == 0x01)) {
        return APP_PROTO_TLS;
    }

    // SSLv3/TLS Record
    uint8_t content_type = data[0];
    uint8_t version_major = data[1];
    uint8_t version_minor = data[2];

    // Content Type: Handshake (0x16)
    if (content_type == 0x16 &&
        version_major == 0x03 &&
        version_minor <= 0x04) {
        return APP_PROTO_TLS;
    }

    // Application Data (可能是会话恢复)
    if (content_type == 0x17 &&
        version_major == 0x03 &&
        version_minor <= 0x04) {
        return APP_PROTO_TLS;
    }

    return APP_PROTO_FAILED;
}

void tls_proto_register(void)
{
    // 注册probing parser（端口443）
    proto_detect_register_probing_parser(
        IPPROTO_TCP,
        443,
        APP_PROTO_TLS,
        5,   // min_depth
        5,   // max_depth
        tls_probing_parser,  // ToServer
        tls_probing_parser   // ToClient (same)
    );
}
```

### 4.3 DNS协议识别

#### 识别特征

```
DNS Header (12 bytes):
  +------+------+------+------+------+------+
  | ID   | Flags| QDcnt| ANcnt| NScnt| ARcnt|
  +------+------+------+------+------+------+
    2B     2B     2B     2B     2B     2B

Flags:
  QR (bit 15): 0=Query, 1=Response
  Opcode (bit 11-14): 0=Standard Query

Query必须满足:
  - QDcount >= 1 (至少1个查询)
  - ANcount == 0 (查询没有应答)
  - Opcode == 0 (标准查询)
```

#### Probing Parser实现

```c
static app_proto_t dns_probing_parser(
    const uint8_t *data, uint32_t data_len, uint8_t direction)
{
    if (data_len < 12)
        return APP_PROTO_UNKNOWN;

    uint16_t flags = (data[2] << 8) | data[3];
    uint16_t qdcount = (data[4] << 8) | data[5];
    uint16_t ancount = (data[6] << 8) | data[7];

    uint8_t qr = (flags >> 15) & 0x01;
    uint8_t opcode = (flags >> 11) & 0x0F;

    // 标准查询
    if (opcode == 0) {
        // 查询：QR=0, QDCOUNT>=1, ANCOUNT=0
        if (qr == 0 && qdcount >= 1 && ancount == 0) {
            return APP_PROTO_DNS;
        }
        // 响应：QR=1, QDCOUNT>=1
        if (qr == 1 && qdcount >= 1) {
            return APP_PROTO_DNS;
        }
    }

    return APP_PROTO_FAILED;
}

void dns_proto_register(void)
{
    // DNS over TCP (port 53)
    proto_detect_register_probing_parser(
        IPPROTO_TCP, 53, APP_PROTO_DNS,
        12, 12, dns_probing_parser, dns_probing_parser
    );

    // DNS over UDP (port 53)
    proto_detect_register_probing_parser(
        IPPROTO_UDP, 53, APP_PROTO_DNS,
        12, 12, dns_probing_parser, dns_probing_parser
    );
}
```

## 6. 性能优化考虑

### 6.1 避免重复检测

- 在Flow中缓存检测结果(`alproto`字段)
- 使用检测标志位(`proto_detect_flags`)
- 一旦检测成功或失败，不再重复检测

### 6.2 快速路径优化

```c
// 端口快速映射
static inline app_proto_t fast_port_lookup(uint8_t ipproto, uint16_t port)
{
    if (ipproto == IPPROTO_TCP) {
        // 常见端口直接映射
        switch (port) {
        case 80:
        case 8080:
        case 8000:
            return APP_PROTO_HTTP;
        case 443:
        case 8443:
            return APP_PROTO_TLS;
        case 53:
            return APP_PROTO_DNS;
        case 22:
            return APP_PROTO_SSH;
        case 21:
            return APP_PROTO_FTP;
        case 25:
            return APP_PROTO_SMTP;
        default:
            return APP_PROTO_UNKNOWN;
        }
    }
    return APP_PROTO_UNKNOWN;
}
```

### 6.3 Pattern匹配优化

- 初期使用简单的`memcmp`/`strncasecmp`
- 后期可集成Hyperscan或AC自动机
- 限制检测深度（如前100字节）

### 6.4 数据准备优化

- 只在有足够数据时触发检测（如>=12字节）
- 利用DPDK的prefetch机制
- 避免不必要的内存拷贝

## 9. 扩展性设计

### 9.1 添加新协议

添加新协议只需3步：

1. **在`app_proto.h`中添加枚举**
```c
typedef enum {
    // ...
    APP_PROTO_MQTT,    // 新增
    APP_PROTO_MAX
} app_proto_t;
```

2. **实现probing parser**
```c
static app_proto_t mqtt_probing_parser(
    const uint8_t *data, uint32_t data_len, uint8_t direction)
{
    // 检测MQTT CONNECT报文
    if (data_len < 2)
        return APP_PROTO_UNKNOWN;

    // MQTT固定头: 0x10 (CONNECT)
    if (data[0] == 0x10) {
        return APP_PROTO_MQTT;
    }

    return APP_PROTO_FAILED;
}
```

3. **注册协议**
```c
void mqtt_proto_register(void)
{
    proto_detect_register_probing_parser(
        IPPROTO_TCP, 1883, APP_PROTO_MQTT,
        2, 10,
        mqtt_probing_parser, mqtt_probing_parser
    );
}
```
